Informed Search

Uninformed search knows nothing about where the goal is. Informed search uses a heuristic h(n) — an estimate of distance to the goal — to search smarter: Greedy, Beam Search, Hill Climbing, and A*.

Recap from Lab 01

Uninformed → informed

Uninformed search uses only the problem definition — no idea where the goal is (see Lab 01). Informed search adds a heuristic function that estimates distance to the goal, so the search can prefer states that look closer. Completeness, optimality, time (b, d, m) and space still apply — informed search just uses them differently.

Foundation

Heuristics

A heuristic h(n) estimates the cost from state n to the nearest goal. It's problem-specific — computed from the state alone, with no search involved. Try two classic 8-puzzle heuristics on the same start/goal pair below.

One idea, three sizes of frontier

Greedy · Beam Search · Hill Climbing

All three rank the frontier by h(n) alone (ignoring cost paid so far) — they only differ in how much of the frontier they keep:

  • Greedy best-first: priority queue by h(n), no size limit. Complete/optimal: No. Time/space: O(bm).
  • Beam search: greedy, but only the best l nodes survive each round. Complete/optimal: No. Time: O(bml). Space: O(bl).
  • Hill climbing: beam search with l = 1 — keep only the single best node, no backtracking. Complete/optimal: No (random-restart hill climbing overcomes local maxima — trivially complete). Time: O(bm). Space: O(b).

Beam search and hill climbing suit optimization (iteratively improve one solution) more than pathfinding; beam search shows up constantly in NLP (machine translation, summarization) picking the most probable sequence of words.

A* and its optimality

A* avoids expanding paths that are already expensive by scoring nodes with f(n) = g(n) + h(n): cost so far, plus estimated cost to the goal. Switch the playground above to A* — on this graph, greedy/beam/hill-climbing all get lured toward G through a node with tempting low h but a costly edge; A* isn't fooled, because it also accounts for g(n).

  • Complete: Yes. Optimal: Yes — A* never expands a node with f(n) > C*.
  • Time/space: O(bd), using a priority queue.

Admissible vs. consistent

Admissible: h(n) ≤ h*(n) — never overestimates the true remaining cost. Consistent: h(n) ≤ cost(n, n') + h(n') for every neighbor n' — the heuristic can't drop by more than the actual step cost. Consistent ⟹ admissible, but not the other way round. Tree-search only needs admissibility to be optimal; graph-search needs consistency (otherwise a cheaper path to an already-expanded node can be missed).

Not all admissible heuristics are equal

Choosing a heuristic

Back to the puzzle: h₁ (misplaced tiles) and h₂ (Manhattan distance) are both admissible and consistent — but h₂(n) ≥ h₁(n) for this state (14 ≥ 6), so h₂ dominates h₁ and guides A* with fewer node expansions. Given any two admissible heuristics ha, hb, their max — h(n) = max(ha(n), hb(n)) — is also admissible, and dominates both.

Proof strategy for admissibility: build h(n) as the exact cost of a relaxed version of the problem (fewer constraints on actions). A relaxed problem's optimal cost is always ≤ the real problem's, so h(n) ≤ h*(n) for free. Manhattan distance is exactly this: it relaxes "a tile can only move into the blank" to "a tile can move straight to its goal cell," ignoring collisions.

Bounded memory

IDA* & Simulated Annealing

IDA* = Iterative Deepening + A*'s evaluation function as the depth-limit threshold: run a depth-limited search with the cutoff on f(n) instead of depth, increasing the threshold each iteration. Complete & optimal (unit cost), but O(bd) time with only O(bd) space — a DFS-shaped A*. Memory-bounded A* is the equivalent idea combined with beam search: keep only l nodes in the queue.

Simulated annealing escapes local maxima the opposite way hill climbing gets stuck: it allows some "bad" moves, accepted with probability exp(−Δ/T), and gradually cools T so bad moves become rarer over time.

–
P(accept worse move) = exp(−Δ/T)

High T, small Δ → almost always accept (explore). Low T, large Δ → almost never accept (settle). As T → 0 over time, this converges to hill climbing. Watch: simulated annealing

Same algorithms, real papers

Research connections

These algorithms aren't just puzzle-solvers. Same three ingredients every time — search node, action, frontier/heuristic — applied to prompts, proofs, code, and molecules instead of grids.

Greedy / Best-First

Classical Planning with LLM-Generated Heuristics

Challenging the State of the Art with Python Code · NeurIPS 2025 · arXiv:2503.18809
Core idea
Instead of hand-crafting a planning heuristic, ask an LLM to write one as Python code; generate several candidates, keep whichever solves training problems fastest.
Problem
Domain-independent planning heuristics are hard to design by hand; letting the LLM output a full plan directly is unreliable on unseen tasks.
How the algorithm fits
Unchanged Greedy Best-First Search: states are planning states, actions are the domain's operators, and h(n) is literally the LLM-generated function ranking the frontier — GBFS still always expands the lowest-h(n) node.

LeanDojo: Theorem Proving with Retrieval-Augmented Language Models

Yang et al. · NeurIPS 2023 · arXiv:2306.15626
Core idea
ReProver is a theorem-prover LM: it repeatedly proposes the next proof "tactic," retrieving relevant lemmas from a huge math library to help decide.
Problem
Prior LLM theorem provers were unreproducible and bad at picking the right lemma from a large library.
How the algorithm fits
Search leaves grid-world entirely: a proof state is the search node, a tactic is the action, and best-first search explores the proof tree, expanding the state with the highest cumulative probability of its proof so far. Search isn't just for route planning.

Hill Climbing / Local Search

Gradient Coordinate Descent

classical optimization method, not a single paper
Core idea
Optimize one coordinate (variable) at a time, holding the rest fixed, choosing which coordinate to move next using gradient information — cycle until convergence.
How the algorithm fits
It is hill climbing in disguise: current point = search state, one-coordinate moves = the neighborhood, gradient magnitude = the heuristic for picking the next move.

Plum: Prompt Learning using Metaheuristic

Pan et al. · ACL Findings 2024 · 2024.findings-acl.129
Core idea
Finding a good LLM prompt is a search over a huge space of text strings. Plum tries six classic metaheuristics — including hill climbing and simulated annealing — to find human-readable prompts.
Problem
Prompt optimizers need to be automatic, discrete, black-box, gradient-free, and interpretable — most methods only hit some of these.
How the algorithm fits
A prompt is the search node; an LLM-based edit is the action; task accuracy is the heuristic/fitness. Hill climbing accepts a neighbor only if it scores higher, stopping when no neighbor improves.

PROTEGE: Prompt-based Diverse Question Generation from Web Articles

Puranik, Majumder, Chaoji (Amazon) · EMNLP Findings 2023 · 2023.findings-emnlp.362
Core idea
Generate many candidate FAQ questions from an article, then hill-climb over which subset to keep, balancing diversity and faithfulness to the source.
Problem
Automatically building a diverse, accurate FAQ knowledge base from long web articles.
How the algorithm fits
The search node is a candidate subset of questions; a move swaps one question in/out; the heuristic is a diversity+fidelity score; hill climbing keeps improving the subset until no swap helps.

Synthesizing Programmatic RL Policies with LLM Guided Search

Liu et al. · ICLR 2025 · arXiv:2405.16450
Core idea
Use an LLM to write a starting program (an interpretable RL policy), then run "Scheduled Hill Climbing" to keep improving it.
Problem
Searching program space for an RL policy from scratch takes tens of millions of environment interactions; an LLM can jump-start the search.
How the algorithm fits
A candidate program is the node; an LLM-guided edit is a neighbor; reward in the environment is the heuristic; a "schedule" controls exploration over time — hill climbing with a cooling-like control, close to simulated annealing.

Let's Revise Step-by-Step (ReLoc)

A Unified Local Search Framework for Code Generation with LLMs · NeurIPS 2025 · arXiv:2508.07434
Core idea
Instead of a big search tree of partial code, keep one candidate solution and repeatedly revise it, always keeping the best version seen so far.
Problem
Tree search over code is expensive; pure single-candidate revision struggles because pass/fail feedback is too coarse to tell good edits from bad ones.
How the algorithm fits
The node is the current best program; the neighborhood is LLM-generated revisions; a learned reward model replaces coarse pass/fail as the heuristic; the update rule is classic hill climbing — greedily keep the best-scoring neighbor.

Beam Search

Collaborative Beam Search

Enhancing LLM Reasoning via Collective Consensus · Xu, Ren, Zhang · EMNLP 2025 · 2025.emnlp-main.574
Core idea
Several different LLMs propose reasoning steps together; instead of a separate verifier model, the group's shared perplexity votes on which steps survive.
Problem
Single-model beam search for reasoning inherits that one model's blind spots and usually needs an expensive extra verifier.
How the algorithm fits
A partial reasoning trajectory is the node; the next step (from several LLMs) is the action; the beam keeps the top-B trajectories, scored by cross-model consensus instead of one learned verifier.

SOAR — Search or Accelerate

Confidence-Switched Position Beam Search for Diffusion Language Models · Cao et al. · ICML 2026 · arXiv:2602.10953
Core idea
Diffusion LMs greedily decide which masked position to reveal next; SOAR detects low confidence and temporarily switches to beam search over alternative reveal-orders, then switches back to fast greedy decoding once confident.
Problem
A single bad greedy commitment early on can lock a diffusion LM into a bad token order on hard reasoning problems — but always searching would be too slow.
How the algorithm fits
The node is a partially-unmasked sequence with a confidence score; the beam holds K candidates; low confidence triggers single-position beam branching, high confidence collapses back to parallel greedy decoding.

Panini: Continual Learning in Token Space via Structured Memory

ICML 2026 · arXiv:2602.15156
Core idea
New documents are converted into a growing graph of question-answer pairs; at query time, the system traverses the graph for the most likely multi-hop reasoning chain instead of re-reading raw text.
Problem
Standard RAG re-reasons over raw chunks repeatedly and can retrieve irrelevant context.
How the algorithm fits
A partial inference chain through the graph looks exactly like a beam-search state — but the abstract doesn't use the words "beam search" explicitly, so treat this one as a plausible, unconfirmed connection rather than a verified fact.

LLM Program Optimization via Retrieval Augmented Search (RAS)

Anupam, Shypula, Bastani · ACL Findings 2026 · arXiv:2501.18916
Core idea
Beam-search over candidate optimized rewrites of a slow program; at each step, retrieve similar past "slow → fast" examples and show them to the LLM as in-context guidance before it edits.
Problem
LLMs asked to speed up code with no guidance often produce mediocre or unsafe edits.
How the algorithm fits
A candidate program version is the node; a retrieval-guided LLM edit is the action; the beam keeps the top-B candidate versions by correctness/speed at every step.

A*

Path Planning using Neural A* Search

Yonetani, Taniai, Barekatain, Nishimura, Kanezaki · ICML 2021 · ICML page
Core idea
A CNN looks at a map and predicts a "guidance map" of which regions likely lie on the shortest path; A* then searches using that as its heuristic, made differentiable so the whole thing trains end-to-end.
Problem
Hand-designed heuristics (e.g. Euclidean distance) don't exploit learnable structure in real maps, causing excessive node expansion.
How the algorithm fits — the key point
A* itself is untouched: still f(n)=g(n)+h(n), still expands the lowest-f frontier node. The network does not replace A* — it only learns what A* uses as h(n).

KeeA*: Epistemic Exploratory A* Search via Knowledge Calibration

Zhao, Tu, Sun, Xu · NeurIPS 2025 · OpenReview
Core idea
A learned heuristic's error is itself uncertain. Instead of always expanding the lowest-f node (or sampling randomly), KeeA* clusters frontier nodes and uses the heuristic's own uncertainty to decide which clusters to explore.
Problem
Learned heuristics have systematic biases from limited training data; blind trust — or blind random exploration — both waste search effort.
How the algorithm fits
Same node/frontier/h(n) setup as A*, but node selection becomes a knowledge-calibrated, clustered sampling step instead of strict "always expand the minimum." Evaluated on retrosynthetic chemistry planning and circuit design.

Learning Admissible Heuristics for A*: Theory and Practice

Futuhi, Sturtevant · ICLR 2026 · arXiv:2509.22626
Core idea
Neural heuristics are powerful but usually aren't trained to respect admissibility. This paper's Cross-Entropy Admissibility (CEA) loss explicitly trains a network to stay admissible, with proven sample-complexity bounds for generalizing to new instances.
Problem
Learned heuristics can overestimate true cost, silently breaking A*'s optimality guarantee, with no guarantee they'll work on unseen problems.
How the algorithm fits
Directly next to this lecture: h(n) is a neural net trained to satisfy h(n) ≤ h*(n), which is exactly the condition that keeps A* optimal. Evaluated on Rubik's Cube against pattern-database heuristics.

FaSTA*: Fast-Slow Toolpath Agent with Subroutine Mining

for Efficient Multi-turn Image Editing · ICLR 2026 · arXiv:2506.20911
Core idea
An LLM plans an image edit as subtasks; a subtask matching a previously learned "subroutine" is reused instantly (fast path); a genuinely new subtask falls back to A* search over tool-call sequences (slow path), and successes get mined into new subroutines.
Problem
Re-running expensive tool search for every subtask — even repetitive ones — wastes cost; most subtasks aren't actually novel.
How the algorithm fits
The node is a partial toolpath applied to the image; the action is invoking one editing tool; A* searches this space, but only when no reusable subroutine already solves the subtask (reported: ~91% of tasks skip search entirely).
